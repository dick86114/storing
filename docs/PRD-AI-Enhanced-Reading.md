**文档版本：** v1.0  
**最后更新：** 2026-11-14  
**文档状态：** 已确认交互方向，待开发评审

## 1. 产品定位

AI 增强阅读是 Storing 从“收藏与短摘要”升级到“帮助用户理解文章”的能力。用户在需要时对单篇文章触发“深度解析”，系统异步生成结构化深度报告，覆盖论证结构、关键事实、多观点、风险边界、行动建议和延伸问题。

深度报告不替代现有智能摘要、标签和分类；它是一次显式触发的高成本增强分析，以服务端数据为唯一可信来源，供 Web、Android、macOS 跨端查看和重新生成。

## 2. 两阶段范围

### 2.1 第一阶段目标

让用户对高价值文章显式触发一次深度分析，在不等待页面的情况下获得跨端可读、可追溯、可重新生成的结构化报告，并能从文章列表快速识别哪些文章已经有深度报告。

### 2.2 非目标

- 第一阶段不自动为所有文章生成深度报告。
- 不替换现有智能摘要、标签和分类。
- 不提供本地离线生成；离线只读取已缓存报告。
- 不做多人协作、评论或报告共享编辑。
- 不在第一阶段引入联网检索和多文章知识网络。

### 第一阶段：单篇深度报告

- 单篇文章手动触发深度解析。
- 服务端异步队列执行，提交后立即返回任务状态。
- 生成完成后通过应用内提醒、文章列表状态图标和系统通知告知用户。
- 报告服务端持久化并保留历史版本。
- Web、Android、macOS 均可查看当前报告。
- 任一端可重新触发生成，运行中状态跨端一致。
- 生成中不重复扣费；已有报告在重新生成失败时保持可读。
- 离线时仅读取已缓存报告，不提交新任务。
- 正文更新后，旧报告标记“基于旧版正文”，提供重新解析入口。

### 第二阶段：增强研究与知识网络

- 联网检索补充资料，引用来源必须可追踪。
- 多篇文章关联解析，生成主题级报告。
- “内容发芽”知识网络：从文章、概念、数据和观点生成关联节点。
- 深度报告分享页、批量生成策略和自动触发规则。
- 报告对比、差异识别和知识图谱导航。

## 3. 核心用户流程

1. 用户在文章详情或阅读器点击“深度解析”。
2. 前端立即显示解析中状态，接口返回 `jobId`。
3. 用户可离开页面或切换设备。
4. 服务端生成成功后保存报告，并生成用户通知。
5. 文章列表显示深度报告图标；点击图标进入报告。
6. 任一端打开报告时拉取服务器最新版本并更新本地缓存。
7. 任一端可重新解析；新版本成功前旧版本始终可读。

### 3.1 异常与边界流程

- **模型未配置：** 提交失败并引导用户打开 AI 设置；已有报告仍可查看。
- **AI 调用失败：** 任务进入失败状态，展示错误码、中文原因和重试按钮；旧报告保持当前版本。
- **任务重试期间退出：** 任务仍在服务端继续执行，重新打开文章时恢复状态。
- **重复提交：** 同一用户同一文章已有排队或运行任务时，返回原任务，不新建任务。
- **正文更新：** 报告标记为“基于旧版正文”，继续可读，重新解析后生成新版本。
- **离线打开：** 读取本地缓存报告；重新生成按钮禁用并说明需要网络。
- **权限变化：** 游客或无权访问文章时，不允许提交和读取报告。
- **版本恢复：** 恢复历史版本只切换当前指向，不删除其他版本。

## 4. 数据与接口设计

### 4.1 服务端数据

新增 `article_deep_analyses` 表：

| 字段 | 说明 |
|------|------|
| id | 报告 ID |
| user_id / article_id | 归属用户与文章 |
| status | queued / running / succeeded / failed |
| content_hash | 输入正文指纹，用于判断报告是否过期 |
| report_json | 结构化报告 |
| report_markdown | 渲染用 Markdown |
| model / prompt_tokens / completion_tokens / total_tokens | 生成审计信息 |
| content_truncated | 是否截断长文 |
| error_code / error_message | 失败信息 |
| is_current | 当前报告标记 |
| version | 版本号 |
| created_at / finished_at | 时间信息 |

任务队列复用现有 AI 生成任务基础设施，但增加 `analysis_type = deep_reading`，与普通摘要任务隔离，不写回 `article_metadata.ai_status`。

### 4.2 列表与详情字段

文章列表和详情返回：

```json
{
  "hasDeepAnalysis": true,
  "deepAnalysisStatus": "succeeded",
  "deepAnalysisGeneratedAt": "2026-11-13T10:00:00Z",
  "deepAnalysisVersion": 2,
  "deepAnalysisStale": false
}
```

### 4.3 API

- `POST /articles/:id/deep-analysis`：提交生成或重试，返回 `jobId/status`。
- `GET /articles/:id/deep-analysis`：获取当前报告。
- `GET /articles/:id/deep-analysis/versions`：获取历史版本。
- `POST /articles/:id/deep-analysis/:version/restore`：恢复历史版本。
- `GET /notifications`：应用内通知列表。
- `PATCH /notifications/:id/read`：标记已读。

所有文章级接口必须校验当前用户对文章的数据空间归属；不能依赖客户端传入 `userId`。

## 5. 报告结构

1. **一段看懂**：面向决策的执行摘要。
2. **核心论点**：作者主张、前提和结论。
3. **论证链路**：证据、推理与因果关系。
4. **关键信息与数据**：原文事实、数字、来源位置。
5. **不同观点**：支持、反对、条件适用与可替代解释。
6. **风险与局限**：论证薄弱点、样本限制、隐含假设。
7. **行动指引**：用户可执行建议与触发条件。
8. **延伸问题**：继续研究的问题清单。
9. **阅读路径**：先读什么、再读什么、可跳过什么。
10. **原文引用锚点**：所有关键结论回到原文位置。

报告必须区分“原文事实 / 模型推断 / 行动建议”，不得编造外部数据。第一阶段不联网检索。

### 5.1 提示词与输出约束

- 输出必须是可校验 JSON，再由服务端渲染 Markdown。
- 每个观点必须带 `stance`：`support`、`oppose`、`conditional`。
- 每个关键结论尽量带 `quoteAnchor`，至少标明段落或章节位置。
- 未在原文出现的数据不得作为事实输出；模型推断必须标注为推断。
- 输出超出限制、JSON 无效或必填结构缺失时任务失败并进入现有重试策略。

## 6. 客户端设计

概念交互稿：`docs/ui/ai-enhanced-reading.html`。按现有三端界面结构落地的交互原型：`docs/ui/ai-enhanced-reading-current.html`。两个文件均可在浏览器中直接打开；后者是实现前优先评审的版本。

### 6.1 Web

- 列表卡片右上角显示深度报告图标、解析中脉冲、失败红点和过期标记。
- 详情页在智能摘要下方增加“深度报告”入口卡。
- 点击入口打开右侧报告抽屉，支持目录导航、引用锚点、复制 Markdown、历史版本。
- 顶部操作区提供“深度解析”按钮；提交后可关闭页面。
- 浏览器通知需授权，未授权时只使用应用内提醒。

### 6.2 Android

- 文章卡片摘要下方显示报告胶囊标签。
- 阅读器顶部工具栏和底部操作栏均可触达“深度解析”。
- 报告使用底部展开面板，目录横向吸顶，内容纵向滚动。
- 生成完成使用系统通知，点击通知打开对应文章报告。
- 离线时展示缓存报告，重新生成按钮禁用并说明原因。

### 6.3 macOS

- 列表行显示紧凑报告图标和状态。
- 阅读器工具栏提供“深度解析”，报告在右侧面板展示。
- 双栏窗口可左文右报告，单栏时报告覆盖为工作表。
- 使用 `UserNotifications` 发送系统通知，点击通知定位文章。
- 报告缓存遵循账号隔离与现有阅读器缓存生命周期。

## 7. 交互状态

| 状态 | 列表表现 | 详情/阅读器表现 | 允许操作 |
|------|----------|----------------|----------|
| 未生成 | 不显示图标 | 入口卡说明价值 | 生成报告 |
| 排队中 | 灰色图标 + “排队中” | 进度卡 | 取消（可选）、查看旧报告 |
| 生成中 | 蓝色脉冲图标 | 进度卡 + 预计耗时 | 离开页面、查看旧报告 |
| 已完成 | 深度报告图标 | 报告可读 | 查看、复制、历史、重新生成 |
| 失败 | 红点图标 | 错误原因 + 重试 | 重试、查看旧报告 |
| 报告过期 | 黄点/黄角标 | “正文已更新”提示 | 查看旧报告、重新解析 |
| 离线 | 图标仍显示 | 读取缓存报告 | 重新生成禁用 |

## 8. 权限、提醒与数据边界

- 深度报告只归属创建它的用户数据空间，游客不能触发或读取。
- 应用内通知与系统通知只展示文章标题和完成状态，不展示报告正文。
- 系统通知点击后定位到对应文章和当前报告。
- Web 浏览器通知必须先获得授权；拒绝授权时仅使用应用内提醒。
- Android 通知复用系统通知通道策略，遵守省电限制说明。
- macOS 通知复用 `UserNotifications`，点击后激活主窗口。
- 客户端本地缓存按账号隔离，退出登录不得展示上一账号报告。
- 正文或报告删除后，对应本地缓存必须失效。

## 9. 数据观测

- 记录任务状态、失败错误码、重试次数、耗时、模型、输入截断和 Token 用量。
- 记录报告版本、当前版本、内容指纹与过期状态。
- 不记录报告正文到日志，不记录用户 AI Key。
- 观察指标包括提交量、成功率、失败率、平均耗时、Token 成本、报告查看次数和重新生成率。

## 10. 验收标准

- 提交生成接口在任务入队后立即返回，不等待模型完成。
- 同一用户同一文章同时只存在一个活动深度解析任务。
- 深度解析状态不覆盖普通摘要状态。
- 生成失败不影响已有报告和普通摘要。
- 任一端生成后，其他端刷新或打开详情可见。
- 任一端可重新生成，运行中状态一致。
- 列表接口一次返回所有报告状态字段，不逐篇请求。
- 通知点击可定位对应文章和报告。
- 离线时可打开已缓存报告，不可提交新任务。
- Web、Android、macOS 均提供生成、查看、重试、重新生成入口。

### 10.1 分端验收

#### Web

- 列表卡片在现有来源、AI 状态、时间行内展示深度报告状态胶囊，不破坏卡片布局。
- 详情层摘要卡下方展示深度报告入口卡。
- 报告抽屉支持目录/分区切换、引用定位、复制 Markdown 和历史版本。
- 提交后详情层可关闭，重新打开时状态恢复。

#### Android

- 封面卡片在 AI 状态旁展示深度报告状态。
- 阅读器底部操作栏新增“深度”入口，不遮挡收藏、归档、分享。
- 报告使用底部弹层，支持分区导航、历史和重新生成。
- 系统通知点击打开对应文章报告；离线时读取缓存并禁用重新生成。

#### macOS

- 紧凑列表在 AI 状态旁展示深度报告状态。
- 阅读器操作栏新增“深度报告”按钮。
- 报告以右侧 Inspector 浮层展示，保持三栏主结构不变。
- 支持 UserNotifications 提醒、历史版本、复制 Markdown 和账号隔离缓存。
