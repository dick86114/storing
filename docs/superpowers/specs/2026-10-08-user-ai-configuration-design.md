# 账号级 AI 配置与归档触发设计

日期：2026-10-08

## 背景

Storing 当前的 AI 处理与服务端环境变量耦合：`.env` 中的提供商、模型和 API Key 供全站共用。采集完成后，服务端会异步生成摘要和标签；Web 采集因历史上自动进入归档，还会触发 AI 分类。

这个模式存在三个问题：

1. 采集只是“收集”，不代表用户决定留下文章；此时调用 AI 会浪费 token。
2. 全站共享一个模型配置和 Key，用户量增长后无法区分模型选择、额度与用量归属。
3. AI 生成是 fire-and-forget：采集任务已经完成不代表 AI 完成，失败也没有可追踪状态。

本设计把 AI 触发时机后移到用户明确表达留存意图的归档动作，并把模型配置改为账号级资产。

## 目标

1. 所有采集入口只抓取和保存内容，不自动调用 AI。
2. Web、Android、macOS、浏览器扩展、MCP、微信转发导入统一保存到收件箱。
3. 只有用户明确执行归档时，才按用户设置自动触发摘要、标签和分类生成。
4. 每个用户独立配置提供商、Base URL、API Key、模型和自动触发开关。
5. 用户可以关闭“归档时自动触发 AI”；关闭后归档仍正常完成。
6. AI 任务有排队、运行、成功、失败、重试和 token 用量记录。
7. 三端提供 AI 模型设置、模型列表获取、配置测试和任务状态展示。
8. API Key 加密存储，任何接口都不回显明文。

## 非目标

- 不引入平台代付、余额充值或模型计费系统。
- 不做多模型路由、摘要/标签/分类分别使用不同模型的配置。
- 不自动为历史文章批量补生成 AI。
- 不把乾坤戒服务端暴露为通用 chat 代理。
- 不改变正文抓取、图片上传和文章归属逻辑。

## 产品流程

### 采集

所有采集入口统一为：

```text
提交内容 -> 抓取正文/图片 -> 保存全局文章 -> 写入当前用户收件箱 -> 任务完成
```

覆盖入口：

- Web 手动采集；
- Android 手动采集与系统分享；
- macOS 原生采集；
- 浏览器扩展采集；
- MCP `collect_url`；
- Android 与 macOS 微信转发导入；
- API 或系统内部复用采集队列的保存型任务。

采集阶段不调用摘要、标签或分类模型。Web 不再沿用“采集后自动进入归档”的历史行为；已有 Web 采集任务入口完成后也跳转收件箱。

### 归档

归档表示用户决定留下文章，是唯一自动触发 AI 的动作。

| 用户状态 | 归档结果 | AI 行为 |
| --- | --- | --- |
| 自动触发关闭 | 成功 | 不创建任务，状态为 `disabled` |
| 自动触发开启但模型未配置 | 成功 | 不调用模型，状态为 `not_configured` |
| 自动触发开启且配置有效 | 成功 | 创建 AI 任务，状态为 `queued` |
| AI 调用失败 | 归档保持成功 | 状态为 `failed`，展示原因并允许重试 |

归档时用户手动选择分类则直接使用该分类，不请求 AI 分类；但仍生成摘要和标签。用户未选择分类时，AI 从该用户启用中的正式分类里选择，低置信或无法判断时落入“待整理”。

已有有效 AI 结果的文章再次归档或重复归档不自动重算。替换结果必须通过显式“重新生成 AI”操作。

### 发布

发布不再要求 AI 摘要和标签。没有 AI 结果的文章可以发布；公开页只在结果存在时展示摘要和标签区块。

发布动作不自动触发 AI。

### 显式 AI 操作

以下操作仍可调用模型，且不受“归档自动触发”开关影响：

- 已归档文章的手动“重新生成 AI”；
- 管理员在目标用户文章上执行重新生成；
- 分类管理中的“AI 优化分类说明”；
- MCP `summarize_url`。

这些操作必须使用对应目标用户自己的模型配置。未配置时返回明确错误 `AI_NOT_CONFIGURED`，不回退服务端公共 Key。

## 账号级配置

### 数据模型

新增 `user_ai_settings` 表，每个用户一行：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 用户 ID，唯一外键 |
| `provider` | `anthropic`、`deepseek`、`zhipu`、`openrouter`、`custom` 等 |
| `model` | 模型名，可从接口获取，也可手动输入 |
| `base_url` | 仅 `custom` 或显式支持覆盖 Base URL 的提供商使用 |
| `api_key_ciphertext` | AES-GCM 加密后的 API Key |
| `api_key_last4` | 明文 Key 最后 4 位，用于界面识别 |
| `api_key_updated_at` | Key 最近更新时间 |
| `auto_trigger_on_archive` | 归档自动触发，默认 `false` |
| `created_at` / `updated_at` | 时间戳 |

服务端环境只保留一个主加密密钥，例如 `USER_AI_ENCRYPTION_KEY`。该密钥只用于加解密用户 API Key，不代表任何模型提供商。若主加密密钥未配置，用户 AI 保存与调用返回明确部署错误，不降级为明文存储。

### 设置接口

提供当前用户接口：

- `GET /ai/settings`：返回 provider、model、baseUrl、autoTriggerOnArchive、是否已配置 Key、Key 最后 4 位和更新时间。
- `PUT /ai/settings`：保存配置；`apiKey` 留空表示保留已保存 Key。
- `POST /ai/models/discover`：获取可选模型列表。
- `POST /ai/settings/test`：执行一次极小 token 的生成测试。

管理员额外可读写服务账号或目标用户的 AI 配置。管理员写入需要审计，审计详情不包含 API Key。

### 界面

Web、Android、macOS 设置页均增加“AI 模型”区域：

1. 提供商；
2. Custom Base URL；
3. API Key；
4. 获取模型列表；
5. 模型下拉选择或手动输入；
6. 归档时自动生成 AI 开关，默认关闭；
7. 保存；
8. 测试生成。

API Key 输入框保存后清空，界面显示 `已配置 · 1234`。修改 Key 时输入新值即可；留空不会删除已有 Key。删除配置需要单独确认操作。

## 模型列表发现

模型列表请求由服务端执行，浏览器和原生客户端不直接携带用户 Key 访问模型服务商。

### 请求规则

`POST /ai/models/discover` 接受：

- provider；
- baseUrl，仅需要时；
- apiKey，可选。

如果请求中没有 apiKey，则使用当前已保存配置。这样用户可以先保存 Key，再刷新模型列表；也可以在设置页输入尚未保存的 Key 后直接获取列表。

### 提供商接口

- OpenAI-compatible 提供商请求 `GET {baseUrl}/models`；
- Anthropic 使用官方模型列表接口；
- 预设提供商使用服务端登记的 Base URL；
- custom 使用用户配置的 HTTPS Base URL。

返回统一为：

```json
{
  "models": [
    { "id": "deepseek-chat", "name": "DeepSeek Chat" }
  ],
  "cached": false
}
```

模型列表可按 provider、baseUrl 和配置指纹缓存 10 分钟。失败时返回具体原因，例如无模型列表权限、Base URL 无效、认证失败或服务商不可用；同时提示用户可以手动输入模型名。

模型列表成功不代表该模型具备 chat 权限。需要验证真实生成能力时，用户显式点击“测试生成”，测试请求限制输出 token，并在按钮旁说明会消耗少量用户 token。

## AI 任务

### 数据模型

新增 `ai_generation_jobs`：

| 字段 | 说明 |
| --- | --- |
| `id` | 任务 ID |
| `user_id` | 用户 ID |
| `article_id` | 文章 ID |
| `trigger_type` | `archive`、`manual`、`admin`、`mcp_summary` |
| `status` | `queued`、`running`、`succeeded`、`failed` |
| `provider_snapshot` | 创建任务时的提供商 |
| `model_snapshot` | 创建任务时的模型 |
| `error_code` | 稳定错误码 |
| `error_message` | 面向用户的失败原因 |
| `attempts` | 尝试次数 |
| `prompt_tokens` | 输入 token |
| `completion_tokens` | 输出 token |
| `total_tokens` | 总 token |
| `content_truncated` | 输入正文是否被截断 |
| `created_at` / `started_at` / `finished_at` | 时间戳 |

同一用户同一篇文章同时只允许一个未完成任务，用部分唯一索引约束。全局任务并发可配置，初始每个用户并发 1。

任务创建时快照 provider 和 model。用户修改配置不影响已排队或运行中的任务。

### 状态回写

`article_metadata` 增加 AI 状态字段：

- `not_generated`：未生成；
- `disabled`：本次归档因用户关闭自动触发而未生成；
- `not_configured`：自动触发开启但用户未配置模型；
- `queued`；
- `running`；
- `succeeded`；
- `failed`。

状态字段用于列表快速展示，任务表保留完整历史。已有摘要、标签或分类结果的存量文章显示 `succeeded`，不触发补生成。

### 重试

可自动重试：

- 网络失败；
- DNS 暂时失败；
- HTTP 429；
- HTTP 5xx。

不自动重试：

- 401；
- 403；
- 余额不足；
- 模型不存在；
- 输出解析失败。

自动重试采用指数退避，建议最多 2 次额外尝试。用户手动重试不受自动次数限制，但仍受并发约束。

### 服务重启

API 启动时：

1. 将遗留 `running` 任务恢复为 `queued`；
2. 保留 `attempts`；
3. 重新调度未完成任务；
4. 已完成任务不重复执行。

## 模型调用

### 合并调用

归档自动生成默认使用一次模型调用，同时返回：

```json
{
  "summary": "三到五句摘要",
  "tags": ["标签一", "标签二", "标签三"],
  "category_id": 12,
  "confidence": 0.86,
  "reason": "分类理由"
}
```

用户已手动选择分类时，只要求返回 `summary` 和 `tags`，不请求分类。

输出必须经过结构校验：

- 摘要为非空文本；
- 标签为 3 到 5 个非空字符串；
- 分类 ID 必须属于该用户启用中的正式分类；
- confidence 在 0 到 1 之间；
- reason 为可空短文本。

解析失败不覆盖旧 AI 结果，任务失败并返回可理解原因。

### 输入控制

- 正文超长时按配置截断，初始建议 24,000 个字符；
- 截断必须在任务中记录 `content_truncated = true`；
- 分类 prompt 只携带当前用户启用中的正式分类、说明和边界示例；
- 不把用户 API Key 写入 prompt、日志或审计；
- provider 响应中的 token usage 尽量记录；未返回时允许为空。

### 结果写入

摘要、标签和分类在生成成功后一次性写入。手动重新生成时，新结果全部通过校验后才替换旧结果；生成失败时旧结果保持可用。

## 安全设计

### API Key

- 使用 AES-256-GCM 加密，随机 nonce 与认证标签一起存入密文字段；
- 明文 Key 只在请求处理期间存在于内存；
- GET 永不返回明文；
- PUT 留空表示保留原 Key；
- 日志、错误、审计和调试输出过滤 Key；
- 删除用户时级联删除 AI 配置；
- 主加密密钥丢失时已有配置不可恢复，界面必须明确提示需要重新录入 Key。

### Custom Base URL

用户可配置 Base URL 会带来 SSRF 风险，必须通过服务端出站策略：

1. 仅允许 HTTPS；
2. 禁止 localhost、内网、环回、链路本地、组播和保留地址；
3. 解析域名后检查全部 A/AAAA 记录；
4. 禁止重定向到不安全或内网地址；
5. 限制连接与响应超时；
6. 限制响应大小；
7. 仅允许模型配置所需的 `/models` 与 `/chat/completions` 路径。

预设提供商的 Base URL 不允许普通用户覆盖，除非配置项显式声明允许。

## MCP 与管理员行为

- MCP `collect_url` 只采集，不调用 AI。
- MCP `summarize_url` 是显式摘要工具，使用 MCP client owner 的 AI 配置；owner 未配置时返回 `AI_NOT_CONFIGURED`。
- MCP 显式摘要任务同样记录到 `ai_generation_jobs`，`trigger_type = mcp_summary`；结果返回给 MCP 调用方，不写入任何用户文章元数据。
- 管理员替目标用户重新生成时，使用目标用户配置，而不是管理员自己的配置。
- 管理员可以为服务账号配置 AI 模型。
- 管理员可以看到配置是否存在、provider、model 和最后 4 位，不能看到明文 Key。

## 用户感知与用量

三端文章卡片和详情页显示：

- 未生成；
- 已关闭自动生成；
- 未配置模型；
- 排队中；
- 生成中；
- 已完成；
- 失败与失败原因；
- 手动重试；
- 模型名；
- 最近一次 token 用量。

设置页提供最近 AI 任务与 token 汇总。用户可以看到自己的调用次数、成功率和 token 消耗，但平台不提供费用估算。

失败信息必须给出具体诊断，例如认证失败、无模型权限、余额不足、速率限制、模型输出无效，不用统一“AI 失败”掩盖原因。

## 迁移

1. 新增用户 AI 配置表和 AI 任务表。
2. `article_metadata` 增加 nullable AI 状态，历史数据按是否已有结果回填。
3. 所有采集入口改为收件箱，移除采集后 AI 调用。
4. 归档接口改为按用户配置创建任务。
5. 发布接口移除 AI ready 强制校验。
6. 服务端删除模型提供商公共 Key 的运行时回退；现有 `.env` 中模型 Key 不再被读取。
7. 更新 PRD 与功能说明，明确“采集不生成 AI，归档按设置生成”。

存量已有 AI 结果全部保留，不做批量重算或清空。

## 测试计划

### API

- 所有保存型采集入口不调用 AI；
- Web 采集保存为未归档；
- 微信导入不触发 AI；
- 归档在关闭、未配置、已配置三种路径下状态正确；
- 手动分类跳过 AI 分类但仍生成摘要标签；
- 发布不依赖 AI；
- AI 配置按用户隔离；
- API Key 不回显；
- API Key 留空保留；
- custom Base URL 拒绝不安全地址；
- 模型列表接口不泄露 Key；
- 任务并发、恢复、重试和状态回写正确；
- 手动重新生成失败时保留旧结果。

### Web / Android / macOS

- 设置页可保存 provider、Base URL、Key、模型和开关；
- 获取模型列表可用，失败时提示可手动输入；
- 模型可选择也可手动输入；
- 默认关闭自动触发；
- 文章列表和详情显示 AI 状态；
- 失败后可手动重试；
- 采集完成入口跳转收件箱；
- 管理员可代服务账号配置。

## 实施阶段

1. **采集行为统一**：移除采集阶段 AI，Web 改为收件箱，发布移除 AI 强依赖。
2. **账号配置**：新增表、加密存储、设置与模型列表 API、三端设置界面。
3. **归档任务**：新增任务队列、归档触发、状态回写、手动生成和重试。
4. **状态与用量**：三端展示状态、失败原因、模型与 token 用量；补齐管理员代配置。
