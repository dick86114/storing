# 乾坤戒 macOS 原生客户端设计

**状态：** 已确认，待编写实施计划

## 目标

为乾坤戒重建一个纯原生 macOS 客户端，首版完成可日用的采集、资料库整理、原文保真阅读和持续更新闭环。客户端以主窗口为核心，菜单栏与全局快捷键提供辅助采集入口。后续在现有架构上增加完整知识导出、离线、MCP 和管理员能力。

## 成功标准

- Apple Silicon Mac 可以安装、登录、采集、整理、阅读并持续更新。
- 文章阅读优先保持服务端保存的网页完整排版，不为了统一风格重写正文。
- 主窗口在三栏结构中提供高密度浏览、连续阅读和文章管理。
- 菜单栏与全局快捷键可以快速确认并提交当前链接，不需要先打开主窗口。
- 无 Apple Developer 证书时，主应用仍可通过 DMG 分发和应用内更新持续使用。
- 数据模型和模块边界支持后续将完整文章、图片、分类、标签和元数据导出到 Obsidian。

## 平台基线

- 仅支持 Apple Silicon，目标架构固定为 `arm64`。
- 当前基线为 macOS 27、Xcode 27、Swift 6.4。
- 不向下兼容旧 macOS、Intel 或旧 SwiftUI API。
- 使用 XcodeGen 生成 Xcode 工程。
- 不启用 App Sandbox 和 Hardened Runtime。
- 不申请 Developer ID，不执行公证和 stapling。

## 首版范围

### 包含

- 游客浏览和阅读公开文章。
- 用户名与密码登录、退出、刷新会话和撤销当前会话。
- 收件箱、收藏、归档和发布资料库。
- 资料库数量、搜索、排序、分页和归档来源筛选。
- 紧凑文章列表。
- 原生文章信息栏、操作栏和完整 HTML 阅读器。
- 收藏、归档、移回收件箱、发布、重新抓取、重新生成 AI 信息、删除和打开原文。
- 主窗口内手动提交 URL 采集。
- 采集任务列表、状态轮询、失败重试、删除和清理。
- 菜单栏弹窗与全局快捷键采集。
- 应用内检查更新、下载、校验、安装和重启。
- 浅色、深色和跟随系统外观。
- 缓存内容提示、网络错误、空态、加载态和操作反馈。

### 不包含

- 管理员功能。
- MCP 连接管理。
- 离线下载和空间管理。
- Obsidian 或第三方知识库导出。
- macOS 系统分享扩展和 App Group。
- 登录时启动。
- 卡片列表模式和瀑布流。
- 多阅读窗口。
- 浏览器插件任务联动。
- 自建服务器切换或旧域名兼容。

## 产品原则

- 服务端是文章、元数据、任务和用户数据的唯一事实来源。
- 客户端缓存只用于提升启动和切换体验，不把缓存误报为最新数据。
- 完整 HTML 是阅读和后续导出的正文基准。
- Web、Android 和 macOS 共享文章语义，但各自采用符合平台的导航和交互。
- 首版不为低版本兼容牺牲架构，也不提前引入后续模块的复杂度。
- 无证书分发的限制只影响系统扩展能力，不影响主应用核心闭环。

## 视觉系统

### 视觉方向

- 采用 Android 客户端“澄明书斋”方案：浅色为暖珍珠玻璃，深色为深墨绿金。
- 主界面保持安静、克制和高信息密度，不使用装饰性光球、无序渐变背景或强紫色调。
- macOS 原生材质只用于导航、工具栏、弹窗和临时浮层；文章列表和阅读正文使用稳定的实底以保证可读性。
- 品牌资产和装饰元素优先复用 Android 客户端资源，不重新设计另一套视觉符号。

### 材质与层级

- 使用 Android `LiquidGlassRole` 的四级语义：`Panel`、`Chrome`、`Control`、`Accent`。
- 浅色模式使用轻量半透明、顶部亮边和弱阴影；深色模式使用不透明表面与清晰描边，避免发灰。
- 三栏导航和工具栏可以复用 macOS Vibrancy；文章卡片与正文底板不叠加多层材质。
- 正文阅读区域必须保持稳定背景，不随窗口背景或滚动位置改变透明度。

### 文字与形状

- 原生界面使用 San Francisco 系统字体和 SwiftUI 语义字号，不引入自定义品牌字体。
- 阅读正文完全由服务端 HTML 控制，客户端不覆盖正文字体或排版。
- 延续 Android 圆角令牌：控件 `8pt`、分组与面板 `12pt`、弹窗和重点容器 `16pt`。
- 紧凑列表以分隔线和排版层级为主，不使用大面积卡片嵌套。

### 品牌资产来源

- 品牌图形取自 `apps/android/app/src/main/res/drawable/ic_qiankunjie_mark.xml` 和 `apps/android/app/src/main/res/drawable-nodpi/brand_logo.png`。
- 微信来源图标取自 `apps/android/app/src/main/res/drawable/ic_source_wechat.xml`。
- 空状态插图取自 `apps/android/app/src/main/res/drawable-nodpi/empty_library_light.png` 和 `empty_library_dark.png`。
- 文章无封面时的占位渐变沿用 Android `ArticleVisualPalettes` 的四组配色。
- Android Vector Drawable 在 macOS 资源目录中转换为 SVG 或 PDF 矢量资源，保持原始比例、含义和明暗模式差异。
- 系统动作统一使用 SF Symbols；只有品牌和内容来源图形复用 Android 资产，不复制 Android 导航图标。

### 交互与可达性

- 交互反馈以 macOS 的悬停、按下、焦点和键盘导航为主，动画保持短促克制。
- 支持系统减少动态效果、提高对比度和键盘全流程操作。
- 所有强调色、文字和状态颜色在浅色与深色模式下必须满足可读性要求。

## 信息架构

### 主窗口

主窗口采用三栏常驻布局：

- 左栏：收件箱、收藏、归档、发布、采集任务、搜索和设置，并显示资料库数量。
- 中栏：当前位置的文章列表，采用紧凑模式，显示小封面、标题、摘要、来源、时间和标签。
- 右栏：阅读器，使用原生信息栏和操作栏承载元数据与动作，正文区域渲染完整 HTML。

窗口变窄时自动收敛为两级导航：先显示文章列表，再进入阅读详情。恢复宽窗口后回到三栏结构。

### 文章列表

- 默认且首版仅提供紧凑列表。
- 支持标题、来源、原始摘要、AI 摘要、分类和标签搜索。
- 支持按资料库允许的字段排序和正倒序切换。
- 归档页支持按来源筛选和查看来源数量。
- 支持滚动加载、下拉刷新、加载失败重试和空状态。
- 连续阅读时保持列表位置，返回列表不重新跳回顶部。

### 阅读器

- 原生信息栏展示标题、来源、作者、发布时间、当前状态、分类和标签。
- 原生操作栏固定展示收藏、归档、发布、重新抓取、重新生成 AI 信息、删除和更多操作。
- 正文请求桌面版完整 HTML，由受控 `WKWebView` 渲染。
- JavaScript 默认关闭，禁止本地文件访问和任意导航。
- 外部链接交给系统默认浏览器。
- HTML 不可用时展示来源、标题、AI 摘要和文本正文兜底。
- 阅读位置按文章保存，重新打开时恢复最近位置。
- 首版不提供滚动自动隐藏或悬浮工具栏。

### 辅助采集

- 菜单栏图标和全局快捷键都打开同一个菜单栏弹窗。
- 弹窗提供链接输入、读取剪贴板、提交、打开主窗口和最近任务状态。
- 提交前必须确认链接，避免直接采集剪贴板导致误操作。
- 默认快捷键为 `⌥⌘S`，设置中可选择其他组合。
- 任务完成或失败后显示 macOS 通知，点击后打开对应文章或任务。
- 应用内手动采集和辅助采集使用同一套采集状态模型。

### 设置

- 显示当前版本、服务地址和运行环境信息。
- 切换浅色、深色和跟随系统。
- 检查更新，展示版本说明，并执行下载安装。
- 管理当前设备会话。
- 退出登录并清除本机用户态数据。
- 首版不提供登录时启动和系统分享扩展设置。

## 模块架构

首版为模块化单 App，后续功能以新增模块方式接入。

- `AppShell`：应用生命周期、窗口、菜单、快捷键和顶层路由。
- `Core`：共享模型、错误、日期、日志、并发工具和依赖协议。
- `Networking`：URLSession 客户端、请求构造、刷新和重试策略。
- `Auth`：登录、Keychain 会话、刷新、退出和设备会话。
- `Library`：文章列表、搜索、排序、筛选、计数和本地缓存。
- `Collect`：手动采集、菜单栏采集、任务轮询和通知。
- `Reader`：文章详情、操作栏、HTML 阅读器和阅读位置。
- `DesignSystem`：颜色、排版、间距、按钮、状态和通用组件。
- `Updating`：GitHub Release 检查、下载、校验、安装和重启。
- `UILab`：Debug 专用固定数据场景和截图入口。

后续模块：

- `Offline`：正文、封面和图片下载及空间管理。
- `Exporting`：HTML 到 Markdown、图片本地化和知识库输出。
- `MCP`：个人 MCP 连接管理。
- `Admin`：管理员和跨用户资料库。

## 状态与缓存

- 使用 Swift 6 `Observation` 和 actor 隔离，不引入第三方状态框架。
- 列表元数据缓存使用 SwiftData，并在首次实现时建立版本化模型容器。
- 缓存作用域至少包含 `userId`、资料库、搜索词、排序、分类和来源筛选。
- 启动或切换资料库时先显示可用缓存，同时后台请求最新数据。
- 最新数据成功返回后覆盖对应缓存；失败时保留缓存并显示“缓存内容”标识。
- 账号切换或退出登录时立即清理内存状态、任务、计数、筛选和选中文章。
- 其他账号的缓存不得被当前账号读取。
- 完整正文默认只做按需临时缓存，不作为离线能力对外承诺。

## 认证与服务端接口

- 复用现有用户、文章、搜索、分类、标签和 AI 服务。
- 在 `mobile_sessions.client_type` 体系中新增 `macos`。
- 新增 macOS 会话登录、刷新、退出、当前会话和会话撤销接口。
- Access Token 有效期和 Refresh Token 规则与现有原生客户端保持一致。
- 访问令牌在内存中管理，刷新令牌保存在 Keychain。
- 刷新请求必须单飞，多个并发 401 只能触发一次刷新。
- 新增 macOS 专属采集来源和任务接口，不复用 Android 或浏览器插件任务列表。
- 服务端采集队列需要把 `macos` 纳入进程重启后的恢复范围。
- 服务端变更保持向后兼容，不修改 Web Cookie 登录、Android 或浏览器插件现有契约。

## 网络与错误处理

- `Networking` 统一处理超时、认证失败、用户禁用、服务不可用、限流和请求取消。
- 幂等 GET 请求可以有限重试，提交和更新请求不得自动重复执行。
- 错误按以下类别展示：
  - 可恢复网络错误：保留当前内容并提供重试。
  - 需要登录：清除失效会话并进入登录流程。
  - 权限不足：明确用户无权访问。
  - 内容不可用：保留原文入口和可用的摘要信息。
  - 参数或 URL 无效：在提交前就地提示。
- 日志不得包含密码、Access Token、Refresh Token、MCP Key 或正文内容。

## 无证书分发与更新

发布链路参考 MyToken 和 Miaos：

- GitHub Actions 手动触发 macOS 发布，输入版本号和更新说明。
- 发布前校验运行环境具备 Xcode 27 和对应 macOS SDK。
- 构建 Apple Silicon DMG，创建 `macos-vX.Y.Z` GitHub Release。
- 同时上传通用 DMG 名称和带版本号、架构的 DMG。
- 客户端通过 GitHub API 查询 macOS Release，API 失败时回退 Atom。
- 更新检查支持 GitHub 直连和用户可配置的镜像前缀。
- 下载支持进度、断点续传、超时重试和 SHA-256 校验。
- 安装时等待当前进程退出，备份旧应用、复制新版本、启动新版本并清理临时文件。
- 新版本启动失败时保留旧版本备份，并给出可操作的恢复提示。
- 不依赖 Sparkle、Developer ID、公证或 stapling。
- DMG 内包含首次运行说明，明确 macOS 系统要求、Gatekeeper 处理方式和更新方法。

## 测试策略

- 服务端：
  - 覆盖 macOS 登录、刷新、退出和会话撤销。
  - 覆盖 macOS 采集来源及任务隔离。
  - 覆盖服务重启后的 macOS 任务恢复。
- 客户端单元测试：
  - Keychain 会话、单飞刷新和账号切换清理。
  - 缓存作用域、排序、筛选、分页和错误分类。
  - 采集 URL 校验、任务状态转换和更新版本比较。
  - HTML 阅读器的导航策略和安全边界。
- UILab：
  - Debug 构建提供固定登录、三栏资料库、空态、错误、缓存、采集弹窗和阅读器场景。
  - UILab 不访问真实账号、Keychain、生产 API 或用户缓存。
- 验收：
  - 游客公开阅读。
  - 登录、退出、会话刷新和撤销。
  - 连续阅读、收藏、归档、发布、重新抓取和删除。
  - 主窗口采集、菜单栏采集和全局快捷键采集。
  - 账号切换后的缓存隔离。
  - 无证书干净 Mac 上的 DMG 安装、Gatekeeper 处理和应用内更新。

## 后续扩展约束

- Obsidian 导出必须输出完整笔记，包括标题、来源、作者、发布时间、分类、标签、AI 摘要、正文、图片和原文链接。
- 图片导出时下载到附件目录并重写链接，不依赖导出时的外部网络。
- 导出模块以独立协议接入，首要实现 Obsidian，后续可增加其他知识库。
- 离线模块可以复用导出所需的下载和正文处理能力，但不得改变服务端唯一事实来源。
- MCP 和管理员模块只新增导航与业务模块，不重构首版核心数据流。

## 现有草稿处理

- 不延续现有未提交 macOS 草稿的整体结构。
- 从 `master` 新建独立实现，保留原草稿作为参考。
- 只参考现有草稿中已经验证的系统交互思路；更新实现按本设计的 GitHub 发布链路重新编写。
- 首版不保留 `QiankunjieShareExtension` target 和 App Group 依赖。
