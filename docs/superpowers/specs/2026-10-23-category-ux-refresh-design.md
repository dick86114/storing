# 分类体验重构设计

日期：2026-10-23

状态：已批准（2026-10-23）

## 决策摘要

本次重构不继续强化“分类管理页”，而是把分类提升为资料库的一等导航对象，并统一分类选择与创建流程。

核心决策：

1. macOS 在侧栏的“归档”下直接展示分类，点击分类即可查看对应文章。
2. 单篇分类、批量分类和归档分类共用一个可搜索的选择器。
3. 选择器内支持“输入分类名后直接创建并分类”，不再要求先离开当前流程去管理页创建。
4. 新建分类默认只要求名称；说明、收录示例、排除示例和颜色收进“详细规则”可选区域。
5. 首期优先完成 macOS；Android 与 Web 复用同一信息架构和交互契约，随后对齐。

## 背景

用户反馈分类功能存在两个主要问题：

1. 分类入口藏得太深。
2. 创建分类太麻烦。

当前实现强化了这两个问题：

- macOS 的分类管理位于“系统管理 → 分类管理”，与日常浏览分类不在同一个位置。
- 分类筛选只在进入“归档”后，通过顶部一个无展开指示的菜单访问，容易被理解为普通筛选项。
- 管理页的新建分类表单同时展示名称、说明、适合收录、不适合收录和颜色，视觉上像一份必须完整填写的配置表。
- 阅读器内已经有“输入名称后创建并选择”的轻量路径，但没有复用到批量分类和全局创建。
- 批量分类选择器没有内联新建入口，找不到分类时必须中断当前操作。

现有 API 已经允许只提交分类名称，因此主要问题是客户端信息架构和交互成本，而不是数据模型能力不足。

## 目标

1. 用户进入归档后，无需再打开筛选菜单即可看到现有分类。
2. 从文章或批量操作中完成分类分配，正常路径不超过 2 次操作。
3. 用户可以在当前上下文内创建新分类并立即应用，不需要切换页面。
4. 创建一个可用分类只要求输入名称，完整规则编辑按需展开。
5. 分类选择器支持搜索、最近使用、当前分类状态、AI 判断和内联新建。
6. macOS、Android、Web 使用一致的入口层级、命名和结果反馈。
7. 不改变分类归属、AI 分类和归档权限的既有业务语义。

## 非目标

- 不引入多级分类树或标签式分类。
- 不让 AI 自动创建新分类。
- 不改变“分类只用于归档文章”的产品规则。
- 不重做 AI 分类模型、提示词或置信度策略。
- 不新增跨设备同步的“最近使用分类”；首期按用户、设备本地保存。
- 不把分类管理做成复杂的规则编排器。

## 现状审计

| 端 | 当前入口 | 当前创建方式 | 主要问题 |
| --- | --- | --- | --- |
| macOS | 归档页顶部筛选菜单；系统管理中的分类管理 | 管理页完整表单；阅读器可只填名称 | 导航分裂、表单过重、批量流程无法内联新建 |
| Android | 归档/分类相关操作与设置中的分类管理 | 分类管理页完整表单 | 分类不是归档页的稳定导航入口 |
| Web | 归档内容中的分类导航已相对明确 | 分类管理中的完整表单 | 创建仍与日常分类流程分离；可继续统一选择器 |

## 体验原则

### 分类是浏览对象，不只是筛选项

分类应当像收件箱、收藏和归档一样出现在稳定导航中，而不是藏在工具栏菜单里。

### 默认轻量，高级按需

名称是创建分类的唯一必填项。说明和规则用于提高 AI 判断质量，但不应该阻塞创建。

### 在上下文中完成创建

用户正在分类一篇文章时，就应该能在当前选择器里创建分类并立即应用，不应被带去另一个页面。

### 最近使用优先于全量浏览

大多数用户会反复使用少数分类。选择器先展示最近使用，再展示用户自定义顺序下的全部分类。

### 一个动作只表达一个结果

“创建并分类”必须在按钮文案和结果反馈中明确同时完成两件事；如果创建成功但分类失败，不能向用户显示为完全成功。

## 信息架构

### macOS 侧栏

```text
资料库
├─ 收件箱
├─ 收藏
├─ 归档
│  ├─ 全部归档
│  ├─ 待整理
│  ├─ 工作
│  ├─ 技术
│  ├─ 新建分类…
│  └─ 管理分类…
└─ 已发布

系统管理
├─ 历史任务
├─ 设置
└─ 管理员设置
```

规则：

- “归档”主行和“全部归档”都打开未按分类过滤的归档文章。
- 分类子行直接打开该分类下的归档文章。
- “待整理”固定显示在用户分类之前。
- 用户分类按服务端排序展示，并显示文章数。
- “新建分类…”打开轻量创建弹窗。
- 分类列表底部提供“管理分类…”入口，进入完整管理页。
- 系统管理中的旧分类管理入口在迁移期可以保留，但不再作为主要入口。

### macOS 归档页

- 顶部保留分类筛选器，并与侧栏选择同步。
- 当前分类以清晰的标签或面包屑显示在列表标题附近。
- 分类筛选器的菜单指示不能继续完全隐藏，必须明确表达“可展开”。
- 增加一个直接的“新建分类”入口。

### Android 归档页

- 在归档内容顶部展示可横向滚动的分类 Chip。
- 首项为“全部”，随后为“待整理”和用户分类。
- Chip 行末尾保留“管理”入口。
- 选择器使用 Bottom Sheet，不增加新的页面层级。

### Web 归档页

- 保留现有 `CategoryNavigation`。
- 在导航标题或底部增加“新建分类”和“管理分类”动作。
- 分类选择器与 macOS、Android 使用相同的内容顺序和创建语义。

## 核心流程

### 浏览分类

1. 用户点击侧栏或顶部分类项。
2. 资料库切换到归档视图。
3. 分类 ID 成为当前筛选条件。
4. 列表标题显示当前分类名称和文章数。
5. 切换收件箱、收藏或已发布时清除分类选择。

### 单篇分类

1. 用户点击文章中的分类标签。
2. 打开紧凑分类选择器，搜索框自动聚焦。
3. 用户选择分类、选择“由 AI 判断”，或输入名称创建新分类。
4. 成功后关闭选择器并更新文章分类标签。

目标路径：

```text
点击分类标签 → 搜索并回车 → 完成
```

### 批量分类

1. 用户选择多篇文章并点击“设置分类”或“归档并分类”。
2. 打开统一选择器，标题显示目标文章数量。
3. 选择现有分类，或创建新分类并应用到全部文章。
4. 成功后关闭选择器，更新选中文章的状态。

### 全局新建分类

1. 用户点击侧栏“新建分类…”或管理页“新增分类”。
2. 打开轻量表单，只显示名称输入框。
3. 用户可以直接创建，也可以展开“详细规则”。
4. 创建成功后，新分类立即出现在侧栏和选择器中。
5. 从侧栏创建时，创建成功后自动选中新分类并进入其归档列表；从管理页创建时保持当前管理上下文。

### 创建并分类

1. 用户在选择器搜索框中输入分类名称。
2. 没有匹配项时，选择器底部显示“创建‘名称’并分类”。
3. 用户点击后，客户端先创建分类，再执行当前分类分配。
4. 两个动作都成功后关闭选择器并显示“已分类到「名称」”。
5. 创建成功但分类失败时，分类仍然保留，选择器不关闭，并显示“分类已创建，但文章尚未分类，请重试”。
6. 批量分配返回部分成功时，分类仍然保留，选择器保持打开并显示成功、跳过和失败数量；不得误报为全部完成。

## 统一分类选择器

### 展示层级

内容顺序固定为：

1. 搜索框。
2. “由 AI 判断”。
3. “最近使用”。
4. “全部分类”。
5. “新建分类”或“创建并分类”动作。

### 列表内容

- 分类行显示颜色点、名称和当前选中状态。
- 单篇场景显示“当前”标识。
- 批量场景显示目标文章数量，不显示每个分类的文章数。
- 只展示启用中的分类。
- “待整理”作为系统分类固定展示，不可删除。

### 搜索

- 打开时搜索框自动聚焦。
- 支持按分类名称包含匹配。
- 搜索为空时展示最近使用和全部分类。
- 没有结果时展示创建动作。
- 如果输入名称与现有分类完全匹配，优先展示“使用现有分类”，不能显示创建动作。

### 最近使用

- 每次成功分类或创建并分类后，把分类 ID 写入当前用户、当前设备的最近使用列表。
- 最多保留 5 个，按最近使用时间倒序。
- 已删除或停用的分类在下次读取时自动移除。
- macOS 使用 `UserDefaults`，Android 使用本地偏好存储，Web 使用 `localStorage`。

### 键盘与焦点

- `↑`、`↓` 移动当前高亮项。
- `Return` 执行选择或创建。
- `Esc` 关闭选择器。
- 关闭后焦点返回打开选择器的分类标签或批量工具栏按钮。

## 轻量创建表单

### 默认状态

```text
分类名称  [ 例如：产品设计                 ]

▸ 详细规则（可选）

                          [取消] [创建分类]
```

默认字段：

- 名称：必填，最多 40 个字符。
- 颜色：由客户端从预设色板稳定选择，不要求用户操作。

### 详细规则

展开后显示：

- 分类说明。
- 适合收录。
- 不适合收录。
- 手动选择颜色。
- AI 优化分类说明。

这些字段不阻塞创建。说明为空时，界面提示“未填写说明时，AI 会更倾向于把不明确文章放入待整理”，不使用错误态。

### 重复名称

- 客户端在输入时显示同名分类建议。
- 服务端仍然是唯一性判断的最终来源。
- 服务端返回 `CATEGORY_NAME_CONFLICT` 时，不关闭表单，直接定位并高亮现有分类，允许一键改用现有分类。

## 分类管理页

管理页从“大卡片墙”调整为“列表 + 详情”：

```text
[搜索分类]                         [+ 新建分类]

分类列表                        分类详情
├─ 待整理            12 篇       名称
├─ 工作               8 篇       说明
├─ 技术              23 篇       适合收录
├─ 阅读               5 篇       不适合收录
└─ 已停用分类         0 篇       颜色 / 启用状态

                                   [合并分类] [保存修改]
```

规则：

- 列表显示名称、颜色、文章数和启用状态。
- 支持拖拽排序。
- 点击列表行在右侧编辑详情，不再为每个分类展示完整大卡片。
- 系统分类不可重命名、删除或停用。
- 删除用户分类前必须选择接收文章的目标分类。
- 支持把重复分类合并到目标分类。
- 搜索按名称过滤。

## 状态与异常

### 加载

- 侧栏分类已缓存时先展示缓存，再静默刷新。
- 首次加载显示稳定尺寸的占位行，避免侧栏宽度跳动。

### 空态

- 没有用户分类时，侧栏仍展示“待整理”和“新建分类…”。
- 选择器空态提供“创建第一个分类”。

### 网络失败

- 分类目录加载失败时保留已有缓存，并显示可重试提示。
- 创建或分配失败时不关闭选择器，不丢失输入名称和当前选择。

### 分类失效

- 选择器打开期间分类被删除或停用时，提交返回明确错误并刷新分类目录。
- 最近使用列表同步移除失效分类。

### 用户切换

- 清空当前分类选择、选择器草稿和最近使用缓存的内存状态。
- 新用户加载自己的分类目录和最近使用记录。

### 并发操作

- 同一分类的创建按钮在一次请求完成前禁用。
- 批量分配期间禁止重复提交。
- 创建成功与文章分类请求必须使用同一分类 ID，避免按名称重新匹配。

## 技术设计

### API

首期不新增数据库表，复用现有接口：

- `GET /categories`：分类目录与文章计数。
- `POST /categories`：创建分类，名称之外字段均可省略。
- `PATCH /categories/:id`：更新说明、规则、颜色和启用状态。
- `POST /categories/reorder`：保存排序。
- `POST /categories/merge`：合并重复分类。
- `DELETE /categories/:id?targetCategoryId=...`：删除并迁移文章。

“创建并分类”由客户端串联：

1. `POST /categories`。
2. 使用响应中的分类 ID 执行现有单篇或批量分类接口。

这样可以保持创建和文章归属接口的职责边界，同时准确处理部分成功。

### macOS

- 新增统一的 `CategoryCatalogStore`，保存启用和停用分类、文章计数、最近使用及创建动作；导航和选择器只派生启用分类，管理页使用完整目录。
- `AppModel` 持有唯一的分类目录状态，供侧栏、资料库工具栏、阅读器和管理页共享。
- 侧栏分类行设置 `destination = .archive` 和 `selectedCategoryID`，不新增独立内容页面。
- 单篇分类使用锚定在分类标签上的 `NSPopover`；批量分类使用固定宽度 `sheet`。
- 管理页和选择器共用 `CategoryQuickCreateView`，避免两套表单。
- 新建成功后更新共享分类目录，再由侧栏和所有选择器响应，不依赖各自重复请求。

### Android

- 新增归档分类 Chip 行。
- 分类目录由单一 `CategoryCatalogRepository`/ViewModel 提供。
- 单篇和批量选择器复用同一个 Compose Bottom Sheet。
- 最近使用存入按用户分区的 SharedPreferences 或 DataStore。

### Web

- 保留 `CategoryNavigation`，增强为可显示最近使用和新建入口。
- 抽出统一的分类选择弹窗组件。
- 使用 SWR 的分类 key 作为缓存源；创建成功后统一 mutate。
- 最近使用存入按用户分区的 `localStorage`。

## 分阶段交付

### 阶段一：macOS P0

1. 侧栏归档下展示分类、计数和新建入口。
2. 单篇与批量操作共用一个可搜索分类选择器。
3. 选择器支持最近使用、AI 判断和内联创建并分类。
4. 新建分类默认只要求名称，高级规则折叠。
5. 管理页改为“列表 + 详情”，接入轻量创建，并保留完整规则编辑、排序、启停、删除和合并能力。

阶段一完成后，用户无需进入分类管理页即可完成日常分类。

### 阶段二：Android 与 Web 对齐

1. Android 归档页增加分类 Chip 和内联新建。
2. Web 分类导航接入同样的创建和最近使用规则。
3. 三端统一成功、重复名称、部分成功和网络失败文案。

### 阶段三：分类治理与智能增强

1. 管理页支持合并和清理重复分类。
2. 根据名称生成分类说明与边界示例。
3. 展示 AI 分类低置信度和待整理原因。
4. 根据使用频率给出停用或合并建议。

## 验收标准

### macOS 功能验收

- 进入归档视图后，不打开筛选菜单也能看到全部分类和文章数。
- 点击侧栏分类可直接打开对应文章列表。
- 单篇文章可以点击分类标签打开选择器，并在选择后立即更新。
- 批量选择文章后可以创建新分类并应用到全部文章。
- 新建分类默认只需要名称即可成功。
- 同名校验失败时保留用户的输入和当前上下文。
- 创建成功但分类失败时，分类保留且提示清晰。
- 切换用户后不展示上一用户的分类或最近使用。

### 交互验收

- 分类选择器打开后搜索框自动聚焦。
- 键盘可完成搜索、选择、创建和关闭。
- 当前分类、最近使用和全部分类不会混淆。
- 选择器不因加载、错误或空态发生明显尺寸跳动。

### 视觉验收

- 分类颜色、字号、间距和选中态遵循现有设计系统。
- 侧栏分类层级清楚，不挤压收件箱、收藏、归档和已发布。
- 深色模式下颜色点和选中态保持可辨识。
- 使用 UI Lab 固定场景验证分类导航、选择器、创建表单和错误态。

### 性能与稳定性验收

- 分类目录只保留一个共享数据源，打开选择器不重复发起相同请求。
- 分类列表缓存按用户隔离。
- 连续打开、关闭选择器不遗留重复请求或过期响应。
- 删除或停用分类后，侧栏与选择器在一个刷新周期内同步。

## 成功指标

上线后重点观察：

1. 进入归档的用户中，与分类发生交互的比例。
2. 单篇分类平均操作次数和耗时。
3. 新建分类平均耗时。
4. 从打开选择器到完成分类的成功率。
5. 同名分类冲突次数。
6. 无分类归档文章占比。

目标：

- 分类分配正常路径不超过 2 次操作。
- 创建并分类不超过 3 次操作，且只要求一次文本输入。
- 分类入口不再要求先打开筛选菜单。

## 迁移与兼容

- 不涉及数据库迁移。
- 旧分类管理入口在阶段一保留，避免打断已有用户习惯。
- 新客户端继续读取现有分类接口，旧客户端不受影响。
- 最近使用是本地增强信息，不进入服务端同步。
- 分类目录缓存缺失或损坏时按空缓存处理并重新加载，不阻塞归档浏览。

## 待评审确认
