# 管理员删除用户：后端与安卓端设计

**日期：** 2026 年 8 月 1 日
**状态：** 已确认方案，待实现
**范围：** 后端管理员接口、安卓管理员后台；不修改现有文章全局表和普通用户端流程。

## 1. 目标

管理员可以从安卓端用户管理页永久删除普通用户或服务账号，并同步清理该用户的私有数据与登录凭据。操作必须防误触、不可重复提交，并保留管理员审计线索。

当前工程只有用户查询、创建和更新接口，尚不存在 `DELETE /admin/users/:id`，因此安卓端不能单独实现删除按钮，必须先补齐服务端统一契约。

## 2. 权限与保护规则

- 接口仅允许已登录管理员调用。
- 禁止删除当前登录管理员本人，返回 `SELF_DELETE_FORBIDDEN`（409）。
- 禁止删除角色为 `admin` 的账号，返回 `ADMIN_DELETE_FORBIDDEN`（409）。
- 用户不存在时返回 `USER_NOT_FOUND`（404）。
- 安卓端根据目标用户角色提前隐藏或禁用删除入口；后端仍作为最终安全边界。
- 客户端确认弹窗要求管理员输入目标用户名，服务端不依赖该输入作为权限判断。

## 3. 服务端接口

### `DELETE /admin/users/:id`

成功返回 HTTP 200：

```json
{
  "deleted": true,
  "user_id": 42,
  "username": "example-user",
  "cleanup": {
    "article_metadata": 12,
    "collect_jobs": 3,
    "mobile_sessions": 2,
    "mcp_clients": 1,
    "mcp_request_logs_anonymized": 9,
    "admin_audit_logs_anonymized": 4
  }
}
```

失败延续现有 `{ "error": { "code": "...", "message": "..." } }` 格式，并使用既有鉴权中间件。

## 4. 数据生命周期与事务边界

删除操作由一个数据库事务完成；任一步失败即全部回滚。

### 会删除的私有数据

1. `article_metadata`：删除目标用户对文章的个人状态、AI 结果、正文副本及发布标记。
2. `collect_jobs`：删除目标用户尚未完成或已完成的采集任务记录。
3. `mobile_sessions`：删除全部设备刷新会话，使已安装客户端不能再刷新令牌。
4. `mcp_clients`：删除其 API Key 哈希与客户端配置。
5. `users`：最后删除用户本体。

### 会匿名保留的历史数据

1. `mcp_request_logs`：将 `user_id` 和受该用户 MCP 客户端关联的 `client_id` 置空，保留调用量、状态和时间。
2. `admin_audit_logs`：将历史记录中的 `target_user_id` 置空，并在 `detail` 合并写入目标用户名、用户 ID、删除时间和删除动作，使审计页在用户消失后仍能解释历史记录。
3. 删除动作本身新增一条审计日志，`actor_user_id` 指向执行删除的管理员，`target_user_id` 置空，详情记录被删用户的快照与各类清理数量。

### 明确不删除的数据

- `articles` 是可被多个用户元数据引用的共享原始文章表，绝不随删除用户而删除。
- 其他管理员账号、其他用户的 `article_metadata`、全局平台设置均不受影响。

## 5. 安卓端交互

### 入口

在“管理员后台 → 用户”页已有的“编辑用户”弹窗内，底部新增危险操作区：

- 普通用户与服务账号：显示红色描边的“删除用户”按钮。
- 管理员账号：不显示删除入口，避免给出不可完成的操作。

### 二次确认

点击后关闭编辑弹窗并弹出专用确认框：

- 标题：`永久删除用户`
- 正文：展示用户名和会清理的内容类别，说明“此操作不可恢复”。
- 输入框：要求输入完整用户名；不匹配时确认按钮禁用。
- 操作：`取消` 和红色 `永久删除`。

### 执行与反馈

- 发起请求后，确认框内按钮和输入框禁用，并显示进行中状态，阻止重复点击。
- 成功后：关闭弹窗、从当前用户列表即时移除、刷新完整管理数据，并显示“已永久删除用户「用户名」”。
- 失败后：保留确认框与输入，恢复可操作状态，并展示后端返回的具体错误。
- 仓库层继续使用现有 `authenticatedRequest`，确保请求前 token 校验、遇到 401 后至多刷新并重试一次。

## 6. 测试与验收

### 后端契约测试

- 路由存在且使用 `requireAdmin`。
- 非管理员不能删除。
- 删除普通用户的响应具有 `deleted`、用户快照和清理统计。
- 不能删除本人，不能删除管理员账号。
- 删除前后顺序与事务逻辑保证私有数据清理、历史日志匿名化、共享 `articles` 不被删除。

### 安卓单元测试

- Retrofit `DELETE` 路径与响应模型序列化正确。
- `AdminRepository.deleteUser` 使用管理员鉴权重试边界。
- `AdminViewModel.deleteUser` 成功后从列表移除，失败后保留列表并复位提交状态。
- 管理员用户没有删除入口；普通用户 / 服务账号需要用户名匹配后才能确认。

### 构建验证

- 运行 API 相关测试及构建。
- 运行 Android Debug 单元测试和 `assembleDebug`。
- 运行 `git diff --check`。
- 生成新的本地 Debug APK，且不提交、不推送。

## 7. 非目标

- 不提供普通用户自助注销账号。
- 不更改 Web 端现有用户管理 UI；接口会保留为网页后续接入的公共契约。
- 不删除全局文章原文，不做跨用户文章物理去重或清理。
