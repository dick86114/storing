# 归档分类功能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 为 Storing 建立受控的归档分类体系，覆盖 API/数据库、AI 分类、Web、Web 移动端和 Android，并保持来源、标签及历史数据兼容。

**架构：** 分类作为用户级配置实体，文章元数据通过 `category_id` 关联分类；收件箱允许空分类，归档接口在用户未指定分类时调用受控 AI 分类，低置信度统一落到系统分类“待整理”。Web 和 Android 共享 API 契约，三端分别采用桌面侧栏、移动 Tab 和 Android Bottom Sheet 适配交互。

**技术栈：** Hono、Drizzle、PostgreSQL、TypeScript、Next.js 15、React、SWR、Android 现有客户端栈、pnpm。

## 全局约束

- 使用中文界面文案、代码注释和文档。
- 前端命令使用 `pnpm`，不使用 `npm`。
- 不允许 AI 创建预设分类之外的新分类。
- 每篇归档文章必须有且只有一个主分类；收件箱文章可以没有分类。
- “待整理”为系统分类，不可删除。
- 保留现有 `ai_category`、来源、标签、收藏、发布和软删除字段的兼容行为。
- 数据库迁移必须幂等；索引创建遵循现有并发建索引约束。
- 完成前必须运行 API、Web、共享类型和 Android 可执行的验证；无法运行的 Android 真机验证要明确记录。

## 开始开发前的决策冻结

- 第一版只做一级分类。
- 每篇归档文章只允许一个主分类。
- 收件箱默认不分类。
- AI 不能创建分类。
- “待整理”是系统兜底分类。
- 分类是归档主导航，来源是辅助筛选。
- 先完成 API/数据库契约，再并行推进 Web 和 Android UI。
